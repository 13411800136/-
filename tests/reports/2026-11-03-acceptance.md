## 4. 失败、修复与复测（保留历史）

| 编号 | 现象 | 根因 | 修复 | 复测 |
| --- | --- | --- | --- | --- |
| F-01 | 集成测试错误响应是 `{statusCode,code,error,message}`，断言 `error.code` 为空 | 自定义错误处理器在子路由注册之后设置，子上下文仍用 Fastify 默认处理器 | 把 `setErrorHandler` 前移到路由插件注册之前 | 33/33 通过 |
| F-02 | 附件集成测试 500：`ENOENT ...uploads/<uuid>.pdf` | 测试覆盖 `uploadDir` 后未创建目录（`loadConfig` 只创建默认路径） | 测试夹具显式 `mkdirSync(config.uploadDir)` | 附件测试通过 |
| F-03 | E2E 到货步骤 strict mode 命中两个按钮 | 队列中同时存在演示订单与新订单 | 按订单号定位 `.tablet-task` | E2E 通过 |
| F-04 | E2E 最终时间线期望 10，实际 13 | 测试期望漏算 QC/包装/发货触发事件 | 改为 13（订单实际事件数） | E2E 通过 |
| F-05 | 生产反馈后“已提交”提示偶发消失 | 父级 reload 重新挂载卡片，成功态被重置 | 断言改为 Toast“生产反馈已提交” | E2E 通过 |
| F-06 | 幂等重试在部分动作上被状态守卫提前拒绝 | 守卫在 `runIdempotent` 之外先执行 | 将状态/数量守卫移入幂等事务内 | 集成测试重放通过 |
| F-07 | 包装未达应交即可触发发货，可能形成流程死路 | 触发发货只检查 packed>shipped | 增加“已包装≥应交”守卫；`allowedActions` 同步 | 测试通过 |
| F-08 | 质检允许少检，后续无法补齐导致订单卡住 | 最低实现只支持一次质检 | 要求检验量=已完成生产量（一次全检） | 测试通过 |
| F-09 | PowerShell 文本替换把 E2E 脚本中文写成乱码 | 用 `Get-Content`/`Set-Content` 处理 UTF-8 中文 | 直接用文件写入重写脚本；后续不再用 shell 改写中文源码 | E2E 通过 |
| F-10 | 验收脚本利润断言失败 | 脚本把 `margin` 当成带 `%` 的字符串；API 合同返回数值字符串 `70.24` | 修正脚本断言；不改 API 口径 | 验收 19/19 通过 |

## 5. 性能与可用性

本项目没有真实工厂的并发/规模基线，因此**不宣称**生产性能指标。已做：

- 两连接并发库存正确性测试（非吞吐测试）。
- 页面在 1440×900、1024×768 横屏、390×844 窄屏检查：侧栏折叠、表格横向滚动、金额不截断、弹窗可提交、按钮可点。
- 构建产物约 389 KB JS（gzip 113 KB）、61 KB CSS（gzip 12 KB）；本机启动 < 1s。

没有测量 p50/p95、持续负载或数据库在真实订单量下的表现；这些留待有明确环境与样本后补充。
