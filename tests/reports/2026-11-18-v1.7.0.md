本轮四项：现场异常闭环（原 F 能力）、订单撤回/删除、按钮与流水入口 UI 调整、奶油玻璃主题重做。

## 1. 现场异常闭环

| 状态 | 触发 | 数据 |
| --- | --- | --- |
| 待处理 | 现场角色上报 | `status=OPEN`、`acknowledged_at IS NULL` |
| 处理中 | 管理员「开始处理」 | 写 `acknowledged_at/by`，状态由时间戳派生 |
| 已解决 | 管理员「标记解决」 | `status=RESOLVED`、`resolved_at/by`、`resolution_note` 必填 |

- 受理与解决都会通知上报人（`notifyUser`），并写订单时间线 `EXCEPTION_ACKNOWLEDGED` / `EXCEPTION_RESOLVED`。
- 通用 `PATCH /exceptions/:id` 已移除（404），避免绕过流程改状态。
- 页面：统计胶囊（待处理/处理中/已解决）、状态筛选、卡片展示受理人与处理结论。

证据：`tests/evidence/e2e/60-exception-ack.png`、`61-exception-resolved.png`；测试 `notifications-dashboard.test.ts` 覆盖受理→解决→上报人可见。

## 2. 订单撤回与删除

| 动作 | 条件 | 结果 |
| --- | --- | --- |
| 撤回 | 非已完成、非已撤销 | 写 `withdrawn_at`、`withdraw_reason`，置 `cancelled_at`，停止流转；重复撤回 409 |
| 删除 | 已撤销、已撤回或已完成 | 写 `deleted_at`；列表/看板/流水/归档查询隐藏，详情 404；审计与时间线保留 |

- 页面入口：订单详情头区「撤回订单」（不可 12h 撤销时出现）与「删除订单」（已撤销/已完成时出现）。
- 删除需输入订单号确认；删除后跳回列表。
- 测试：`orders-withdraw-delete.test.ts` 3 个用例（撤回留痕/重复拒绝/越权；删除闸门与可见性；删除后不计入看板与流水）。

证据：`62-withdraw-modal.png`、`63-withdrawn-detail.png`、`64-delete-modal.png`。

## 6. 已知限制

- 删除为标记删除，不物理清理；需要彻底移除时先备份再人工处理。
- 撤回不回收采购/生产已产生的记录，只停止后续流转；已发生的成本仍保留在历史与审计里。
- 背景方块为纯 CSS 绘制，不使用参考壁纸的素材文件（仅参考视觉语言，避免版权问题）。
- 玻璃效果依赖 `backdrop-filter`；极旧浏览器会退化为半透明纯色面板，不影响功能。
