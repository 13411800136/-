# v1.4.0 验证记录（2026-11-14）

本文件记录 v1.4.0 三项业务增强的实际执行结果：现场建档、质检不合格处置、订单流水。
所有命令在 `factory-system` 工作区执行；数据来自临时 SQLite 测试库与本机演示库。

## 1. 改动范围

| 模块 | 文件 | 行为 |
| --- | --- | --- |
| 现场建档 | `backend/src/modules/master/auto-create.ts`（新增） | 客户/供应商/配件按名称查找，缺失则同事务建档，编码自动生成 |
| 建单 | `backend/src/modules/orders/routes.ts` | `customerId` 或 `customerName`；`item.partId` 或 `item.partName` |
| 采购 | `backend/src/modules/purchases/routes.ts` | `supplierId`/`supplierName`、`item.partId`/`item.partName` 二选一 |
| 质检 | `backend/src/modules/qc/routes.ts` | 允许不合格数量；PASS/REWORK/SCRAP；返工/报废退回生产 |
| 生产 | `backend/src/modules/production/routes.ts` | 补产容量 = 订单量 + 已判不合格量 |
| 数量口径 | `backend/src/modules/orders/service.ts`、`packing/routes.ts` | 放行量取已处置记录的合格数量 |
| 订单流水 | `backend/src/modules/finance/routes.ts`（新增）、`frontend/src/pages/admin/FinancePage.tsx`（新增） | 实时汇总与按订单明细 |
| 前端 | `NewOrderPage.tsx`、`OrderActionModals.tsx`、`QcPage.tsx`、`OrderDetailPage.tsx`、`DashboardPage.tsx`、`AppShell.tsx`、`line-theme.css` | 现场输入、三选一处置、流水入口与样式 |

无新增迁移：`qc_records.decision` 在 001 中已允许 `PASS/REWORK/SCRAP`，本次只放开路由校验。

## 5. 已知限制

- 不支持部分交付：报废后必须补产到应交量，否则订单停在「生产中」。
- 返工/报废只作用于不合格部分；已合格数量立即计入放行量。
- 复检要求上一轮记录全部处置完毕；未处置时下发复检返回 409。
- 订单流水只含销售、采购、已反馈生产完成量成本，不含人工、电镀与财务结算；数值为预计值。
- 前端 `dist` 变更后必须重启后端：`@fastify/static` 使用 `wildcard: false`，启动时注册文件路由。
